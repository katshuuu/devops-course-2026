# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это указатель на коммит (по сути ссылка на SHA-1/SHA-256). Создание ветки не копирует файлы, поэтому операция почти мгновенная и почти не занимает место.

В классическом SVN ветка — это копия каталога в репозитории (`svn copy` в `/branches`). Даже с дешёвым копированием на сервере ветка живёт как отдельный путь в центральном дереве: переключение, сравнение и слияние тяжелее, зависят от сети и от того, как устроены `svn:mergeinfo`. Из-за этого ветки в SVN используют реже и осторожнее.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет, полноценный коммит в SVN без доступа к центральному серверу сделать нельзя. SVN — централизованная система: ревизия появляется только после записи на сервер. Офлайн можно править рабочую копию, но история и номер ревизии появятся лишь после связи с репозиторием.

В Git коммит локальный: полная история уже есть на машине, а `push` — отдельный шаг.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- Крупные бинарные артефакты и пофайловые checkout без клонирования всего репозитория (legacy CAD, медиа, некоторые корпоративные хранилища).
- Жёсткая централизация и простые права на каталоги, когда политика компании требует одного сервера и привычных ACL.
- Сопровождение старых систем в банках и госсекторе, где миграция на Git дороже, чем поддержка текущего SVN.

Для новых проектов обычно выбирают Git; SVN остаётся инструментом сопровождения legacy.
